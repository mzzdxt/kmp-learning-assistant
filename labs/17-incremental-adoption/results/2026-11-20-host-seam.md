```text

```

compile-only `LegacyExperimentListGatewayFixture` 不 import KMP，却能构造同一个 `ExperimentListViewModel`。

Swift type-check 参数：

```text
-swift-version 6
-strict-concurrency=complete
-warnings-as-errors
```

第一次失败：

```text
call to main actor-isolated instance method 'close()'
in a synchronous nonisolated context
```

原因是同步 `deinit` 直接调用 `@MainActor` protocol method。修复后：

```swift
Task { @MainActor [gateway] in
    gateway.close()
}
```

完整 type-check 通过。

## 当前验证边界

已证明：

- 双端宿主 UI/ViewModel 与 KMP implementation types 解耦；
- legacy/KMP 实现可以在同一 host contract 下编译；
- composition root 选择 KMP adapter；
- adapter 不执行第二次数据写入；
- Swift 6 actor isolation 与 close lifecycle 可编译；
- Android minified Release runtime 路径可达。

未证明：

- 远端 flag 下发与稳定 cohort assignment；
- 真实旧数据库和 KMP database 的 schema/backfill；
- 线上 1%→100% rollout；
- store release 的配置回滚时延；
- 最终 iOS App runtime；
- 真实用户 crash/performance 对比。

Xcode 26.5 仍没有匹配的 iOS 26.5 Simulator runtime，因此 Swift strict compile 不能写成 iOS runtime 通过。

## 结论

本轮没有用第二套生产栈模拟“渐进”。它建立并验证了更关键的结构：

```text
host-owned contract
→ one adapter
→ one composition-root selection
→ one data writer
```

这让回滚的代码影响面收口，但真实生产迁移仍需要 flag/cohort、数据兼容和发布运维证据。
